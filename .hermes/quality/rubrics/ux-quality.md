# UX Quality Rubric

## Purpose

Evaluate whether UX outputs are clear enough to guide prototype and implementation work.

## Required Inputs

- UX flow brief
- Screen list
- User journey
- MVP scope
- Accessibility or role constraints

## Quality Dimensions

| Dimension | What To Check |
| --- | --- |
| Flow clarity | Entry, main path, variants, and exits are described. |
| Screen purpose | Each screen has a job and primary action. |
| State coverage | Empty, loading, error, and permission states are considered. |
| Accessibility | Accessibility and readability risks are noted. |
| Implementation handoff | Data and interaction needs are visible. |

## 5-Point Scoring Criteria

| Score | Criteria |
| --- | --- |
| 1 | Screens are vague or disconnected from user goals. |
| 2 | Basic flow exists but misses key states or roles. |
| 3 | Usable flow with some unresolved UX questions. |
| 4 | Clear UX brief ready for implementation slicing. |
| 5 | Strong UX plan with states, IA, accessibility, analytics, and handoff notes. |

## Pass/Fail Threshold

Pass at 4 or higher. Fail if the primary flow or screen purpose is unclear.

## Common Failure Patterns

- Starts with screens before user journey.
- Ignores empty and error states.
- Uses marketing-style screens for operational tools.
- Leaves data requirements implicit.

## Improvement Guidance

Add user journey, screen purpose, primary actions, states, role differences, and implementation notes.

## Example Of A High-Quality Output

"The UX brief defines a course manager flow from course selection to readiness checklist, learner risk review, issue triage, and export, with empty states, permission notes, and required data for each screen."
