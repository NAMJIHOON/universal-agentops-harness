# Customer Segment Quality Rubric

## Purpose

Evaluate whether target segments are actionable enough for product, UX, and marketing decisions.

## Required Inputs

- Customer segment template
- Buyer, user, and approver notes
- Pain point map
- Segment prioritization criteria

## Quality Dimensions

| Dimension | What To Check |
| --- | --- |
| Role clarity | Users, buyers, and approvers are separated. |
| Priority | Segment priority has a reason. |
| Reachability | Acquisition or access path is plausible. |
| Pain intensity | Segment has a meaningful pain. |
| Decision usefulness | Segment changes scope, UX, or message. |

## 5-Point Scoring Criteria

| Score | Criteria |
| --- | --- |
| 1 | Segment is "everyone" or undefined. |
| 2 | Segment exists but roles and priority are unclear. |
| 3 | Usable segment with some missing evidence. |
| 4 | Clear priority segment with roles, pain, and reachability. |
| 5 | Segment definition drives product, UX, marketing, and validation choices. |

## Pass/Fail Threshold

Pass at 4 or higher. Fail if the primary user is unknown.

## Common Failure Patterns

- Merges buyer and user into one persona.
- Creates decorative personas with no decision impact.
- Ignores excluded or later segments.
- Prioritizes based only on market size.

## Improvement Guidance

Name the primary user, buyer, approver, top pain, reachability path, and why this segment is first.

## Example Of A High-Quality Output

"Primary segment: course operations managers at institutions running 20+ online courses per term. Buyer: program lead. Pain: fragmented launch and learner risk tracking. Reachability: existing education operations communities and institutional pilots."
