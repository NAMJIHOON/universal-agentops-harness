# MVP Scope Quality Rubric

## Purpose

Evaluate whether MVP scope is small, testable, and aligned with the core value proposition.

## Required Inputs

- MVP scope
- PRD or product brief
- Value proposition
- Validation goals
- Constraints

## Quality Dimensions

| Dimension | What To Check |
| --- | --- |
| Focus | Must-have items validate the core promise. |
| Size | Scope fits the intended delivery window. |
| Prioritization | Must, should, could, and later are separated. |
| Dependencies | Blocking dependencies are visible. |
| Validation | MVP success can be measured. |

## 5-Point Scoring Criteria

| Score | Criteria |
| --- | --- |
| 1 | MVP is a full product wishlist. |
| 2 | Scope exists but must-have items are too broad. |
| 3 | Usable scope with some dependency or metric gaps. |
| 4 | Clear MVP boundary ready for sprint planning. |
| 5 | Tight MVP with validation logic, tradeoffs, and release boundary. |

## Pass/Fail Threshold

Pass at 4 or higher. Fail if must-have scope cannot be delivered or validated.

## Common Failure Patterns

- Treats all features as must-have.
- Includes polish before validation.
- Omits non-goals.
- Has no measurable MVP outcome.

## Improvement Guidance

Keep only features needed to test the primary user, pain, and value proposition. Move the rest to later.

## Example Of A High-Quality Output

"Must-have scope includes readiness checklist, learner risk table, and status export. Automated nudges, LMS integration, and advanced analytics are later because the MVP first validates operational visibility."
